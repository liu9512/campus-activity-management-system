# 校园活动管理系统 V1.0

本仓库用于“实验一：基于工程意图的软件迭代开发”。V1.0 是一个无需安装依赖的静态 Web 应用，使用浏览器本地存储保存演示数据，覆盖用户注册登录、学生浏览与报名活动、教师发布与管理活动、报名名单导出和角色权限控制。

## 运行方式

直接用 Edge、Chrome 等现代浏览器打开 `index.html` 即可。不要使用 IE。

## 演示账号

| 角色 | 用户名 | 密码 |
| --- | --- | --- |
| 管理员 | `admin` | `admin123` |
| 活动组织教师 | `teacher` | `teacher123` |
| 学生 | `student` | `student123` |

学生也可以在页面中自行注册新账号。

## 目录结构

```text
index.html          入口页面
styles.css          页面样式
js/store.js         本地数据存储与演示数据
tests/              浏览器端验证入口
```

> 说明：V1.0 使用浏览器 `localStorage` 作为演示数据存储，适合课程实验和单机验证，不用于生产环境。

## 功能清单

- 学生注册、登录与角色权限
- 活动关键词、分类和状态筛选
- 活动详情、报名、取消和“我的报名”
- 教师活动创建、编辑、发布、截止报名和取消
- 报名名单查看与 CSV 导出
- 管理员用户状态管理与操作记录查看

## 自动验证

使用现代浏览器打开 `tests/test-runner.html`，页面会自动执行 9 项验证并显示通过结果。

## V1.0 数据约束

- 同一学生不能重复报名同一活动。
- 活动达到容量上限后不能再新增有效报名。
- 报名截止后不能报名或取消。
- 教师只能管理本人创建的活动。
- 学生、教师、管理员按角色访问对应功能。

## 开发过程与实验分支

`main` 分支保留最终采用的 V1.0，提交历史按项目骨架、认证权限、活动报名、教师管理、自动验证逐步形成。

以下分支用于记录开发过程中评估过但没有采用的方案，均未合并到 `main`：

- `experiment/backend-database`：尝试引入后端 API 和数据库，因课程原型缺少部署环境、会提高复现成本而放弃。
- `experiment/notification-reminder`：尝试实现活动开始前提醒，因需要外部推送、授权和重试机制而移出 V1.0 范围。
- `experiment/recommendation-ranking`：尝试根据历史报名分类推荐活动，因演示数据不足且不属于核心业务闭环而放弃。

这些分支用于体现需求取舍、候选设计和工程判断过程，不代表最终交付版本。
