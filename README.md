# 校园活动管理系统 V2.0

本仓库在 V1.0 基础上完成“实验二：基于用户访谈的需求演化”。系统通过学生、活动组织教师和系统管理员三类角色访谈，新增了报名资格审核、候补队列、自动递补、报名状态透明化和管理员活动监管。

## 运行方式

直接用 Edge、Chrome 等现代浏览器打开 `index.html`，无需安装依赖。

## V2.0 业务规则

- 正式参加人数不能超过活动容量。
- 活动满员后，学生可以进入候补，不再直接拒绝。
- 候补严格按照进入候补的时间排序。
- 正式人员取消后，空余名额自动递补给候补第一名。
- 候补人员可以主动退出，后续人员依次前移。
- 教师可按活动设置是否需要资格审核，并填写参加资格说明。
- 需要审核的活动先进入“待审核”；教师可以审核通过或拒绝。
- 审核通过后仍要检查容量：有名额则正式参加，无名额则进入候补。
- 学生只能查看、取消或退出自己的报名；教师只能审核本人负责的活动。
- 管理员可以启用或停用账号，并对违规或明显错误的活动执行下架和恢复。

## 主要功能

- 学生活动浏览、详情、报名、审核状态和候补位置查看
- 学生撤回申请、取消正式报名和退出候补
- 教师创建、发布、截止和取消本人活动
- 教师配置参加资格和是否审核
- 教师按正式名单、待审核、候补队列处理报名
- 正式人员取消后自动递补候补第一名
- 管理员用户状态管理和全部活动监管
- 报名名单 CSV 导出
